# WaterScript — встроенные скрипты WaterMc

Скрипты лежат в папке `scripts/` рядом с JAR сервера: файлы `*.wsc`, можно во вложенных папках. Файлы и папки, имя которых начинается с `_`, отключены. При первом старте создаётся отключённый пример `scripts/_example.wsc`: переименуйте его в `example.wsc`, чтобы включить.

- `/watermc script reload` — перезагрузить все скрипты без перезапуска сервера.
- `/watermc script status` — что загружено, ошибки, ожидающие выполнения.
- `/watermc script functions` — список функций.
- Настройки в `config/watermc.yml`: `scripts.enabled` (по умолчанию `true`) и `scripts.step-limit` (по умолчанию 200 000).

## Чем отличается от Skript и Denizen

| | WaterScript |
|---|---|
| Где работает | встроен в ядро, отдельный плагин не нужен |
| Скорость | текст разбирается один раз при загрузке. Выражения компилируются в замыкания, переменные — в индексы массива, без рефлексии и без повторного разбора текста |
| Ошибки | опечатки в переменных и функциях, `wait` внутри функции, `cancel` у неотменяемого события, `break` вне цикла ловятся **при загрузке**, с файлом и строкой |
| Изоляция | ошибка прерывает только один запуск обработчика. Она выводится в консоль как `файл.wsc:строка: причина`, одно и то же место — не чаще раза в 10 секунд |
| Защита тика | лимит операций на запуск: бесконечный цикл без `wait` останавливается, а не вешает сервер. Есть ограничения на глубину рекурсии (64), размер списков (100 000) и текста (1 000 000 символов) |
| Песочница | скрипт видит только перечисленные ниже свойства и методы. Нет доступа к файлам, сети, Java-классам и рефлексии |
| Ожидания | `wait` не блокирует сервер: выполнение продолжается через нужное число тиков с того же места, даже внутри циклов |
| Данные | `$переменные` сохраняются в `data/script-variables.wdb` (журнал с защитой от оборванных записей) |

## Синтаксис

Блоки задаются отступом, как в Python. Строка с `:` в конце открывает блок. Комментарии начинаются с `#`.

```
on join:
    send "&aПривет, {player.name}!"
```

- Строки пишутся в `"..."` или `'...'`. `{выражение}` внутри строки подставляет значение. `\{` — буквальная скобка, `\n` — перевод строки. Цвета: `&a`, `&l` и т.д.
- Числа: `10`, `2.5`, `1_000`. Логические значения: `true`, `false`. Пустое значение: `none` (или `null`).
- Списки: `[1, 2, 3]`. Индексы с нуля, отрицательные считаются с конца: `xs[-1]`.
- Операторы: `+ - * / %`, `== != < > <= >=`, `and or not`, `in` / `not in`. `"a" * 3` → `aaa`. Текст + что угодно → склейка.
- Локальные переменные: `set x to 5` или `x = 5`, а также `x += 1`, `-=`, `*=`, `/=`. Живут до конца обработчика.
- Глобальные переменные: `$coins = 10`. Общие для всех скриптов, сохраняются между перезапусками. Хранить можно числа, текст, `true/false` и списки из них. Игрока сохранить нельзя — сохраните `player.uuid`.

### Объявления верхнего уровня

```
on <событие>:            # обработчик события
command /<имя> [аргументы...]:
    @permission "my.perm"         # необязательно
    @permission_message "&cНельзя"
    @description "Описание"
    @usage "/имя <аргумент>"
    @aliases "a", "b"
    ...
every <число> ticks|seconds|minutes|hours:
    ...
function <имя>(<параметры>):
    ...
    return <значение>
```

| Событие | Переменные | `cancel` |
|---|---|---|
| `load` | — | нет |
| `unload` | — (здесь нельзя использовать `wait`) | нет |
| `join`, `quit`, `respawn` | `player` | нет |
| `chat` | `player`, `message` | да, до первого `wait` (обработчик выполняется в основном потоке; поток чата ждёт его не дольше 1 с, `-Dwatermc.scripts.chat-wait-millis`) |
| `player_command` | `player`, `line` (команда без `/`, с аргументами) | да, до первого `wait` |
| `damage` | `player`, `cause` (`fall`, `lava`, `entity_attack`…), `damage` (число) | да, до первого `wait` |
| `interact` | `player`, `block` (или `none`), `action` (`right_click_block`, `left_click_block`, `right_click_air`, `left_click_air`, `physical`) | да: запрещает использование блока и предмета |
| `break`, `place` | `player`, `block` | да, до первого `wait` |
| `death` | `player`, `killer` (игрок или `none`) | нет |
| `kill` | `player`, `entity` (тип моба: `zombie`, `cow`…) | нет |
| `world_change` | `player`, `from` (имя прежнего мира) | нет |

В команде доступны: `sender` (кто вызвал), `player` (игрок или `none`, если вызвала консоль), `args` (все аргументы списком) и именованные аргументы из заголовка (`none`, если не переданы).

### Инструкции

| Инструкция | Что делает |
|---|---|
| `send <текст> [to <игрок/список>]` | сообщение; без `to` — вызвавшему команду, игроку события или в консоль |
| `broadcast <текст>` | всем игрокам и в консоль |
| `console <команда>` | выполнить команду от консоли |
| `log <текст>` | строка в консоль с файлом и номером строки |
| `wait <число> ticks/seconds/minutes/hours` | пауза без блокировки сервера |
| `if … : / else if … : / else:` | условие |
| `while <условие>:`, `repeat <n> times:`, `for x in <список>:` | циклы; `break`, `continue` |
| `stop` | завершить обработчик |
| `cancel` | отменить событие (`chat`, `player_command`, `damage`, `interact`, `break`, `place`) |
| `return [значение]` | выйти из функции |

## Встроенные функции

| Группа | Функции |
|---|---|
| Числа | `random(min, max)` (целое включительно; `random()` — от 0 до 1), `chance(процент)`, `round(x[, знаков])`, `floor`, `ceil`, `abs`, `sqrt`, `pow`, `min(...)`, `max(...)`, `clamp(x, min, max)`, `now()` (мс) |
| Типы | `str(x)`, `num(текст)` (`none`, если не число), `type(x)`, `len(x)` |
| Текст | `lower`, `upper`, `split(текст, разделитель)`, `replace(текст, что, на_что)`, `contains(где, что)` |
| Списки | `list(...)`, `range(от, до)`, `add(список, x)`, `remove(список, x)`, `join(список[, разделитель])` |
| Сервер | `online_players()`, `player(имя)` (игрок или `none`), `world(имя)` |

Члены текста: `.length`, `.upper`, `.lower`, `.trim`, `.contains(x)`, `.starts_with(x)`, `.ends_with(x)`, `.replace(a, b)`, `.split(sep)`.

Члены списка: `.size`, `.first`, `.last`, `.empty`, `.add(x)`, `.remove(x)`, `.contains(x)`, `.join(sep)`, `.clear()`.

## Игровые объекты

**player** — свойства:
- `name`, `display_name`* (вывод в формате `&`), `uuid`, `online`, `op`;
- `health`*, `max_health`, `food`*, `saturation`*, `level`*, `exp`*;
- `gamemode`* (`survival` / `creative` / `adventure` / `spectator`);
- `world`, `x`, `y`, `z`, `yaw`, `pitch`;
- `flying`*, `allow_flight`*, `sneaking`, `ping`, `locale`;
- `item` (предмет в руке), `block` (блок под ногами).

Свойства со `*` можно изменять. Методы:
- `has_permission(p)`, `message(t)`, `actionbar(t)`, `title(t[, sub])`, `kick([t])`;
- `teleport(x, y, z[, мир])` или `teleport(игрок)`;
- `give(предмет[, n])`, `has_item(предмет[, n])`, `take_item(предмет[, n])`;
- `clear_inventory()`, `heal()`.

**block** — свойства: `type`*, `x`, `y`, `z`, `world`, `light`, `powered`, `air`. Методы: `relative(dx, dy, dz)`, `break()`.

**world** — свойства: `name`, `time`*, `storm`*, `thundering`*, `players`, `spawn_x`, `spawn_y`, `spawn_z`. Методы: `block_at(x, y, z)`, `strike_lightning(x, y, z)` (только эффект).

Имена предметов и блоков совпадают с ванильными ключами: `diamond`, `oak_log`, `diamond_ore`.

## Ограничения первой версии

- Набор событий пока ограничен таблицей выше. Добавление нового события — одна строка в `EventSpec` и одна в `BukkitScripts`.
- Чат Paper обрабатывает асинхронно, а скрипты выполняются только в основном потоке. Поэтому поток чата ждёт обработчик `chat` до 1 секунды. Если сервер в этот момент сильно лагает, сообщение уйдёт без отмены, а в консоли появится предупреждение.
- При включённом parallel world ticking обработчики `break` и `place` выполняются в потоке своего мира. Не изменяйте один и тот же `$`-список из разных миров одновременно.
- Скрипты не компилируются в байткод JVM: используются замыкания. Для типичных скриптов этого достаточно. Генерация байткода — следующий шаг, если понадобится.
