# Что выполнено по ТЗ

Работа ведётся поэтапно. Полный аудит и переписывание всех подсистем пока не выполнены. Minecraft, CraftBukkit, Paper, Moonrise, Gale, Pufferfish, Purpur и Leaf сохранены как редактируемые исходники с исходными именами пакетов и API.

При переносе проверены все 5 172 файла Minecraft: они совпали с исходными Git-объектами прежнего Water. Все 2 269 классов собранного API побайтово совпали с прежним Leaf API; добавленных и удалённых классов нет. Отчёты: `source-import-verification.json`, `api-import-verification.json`. Это проверка переноса и байткода API; закрытые плагины она не проверяет.

## Реализовано

1. Независимый Git-репозиторий с модулями `watermc-api` и `watermc-server`. Исходники и ресурсы хранятся напрямую, стек исходных патчей для правки и сборки не нужен. Прежний Water сохранён.
2. Бренд WaterMc в манифестах и сервере, локальный вывод версии, сохранение совместимости с прежними брендами. Основной запускаемый файл — `watermc-1.21.11.jar`.
3. Ранее созданные ограничения визуальных пакетов взрывов, фильтрация метаданных фитиля TNT и выбор FMA с учётом CPU перенесены в Java. Исторические замеры относятся к прежним JAR Water.
4. Добавлен бюджет обычных ванильных частиц на игрока и тик. По умолчанию выключен. Частицы Bukkit API, адресные эффекты, вибрации, принудительные и always-show эффекты проходят без этого ограничения. Отброшенные пакеты не накапливаются в очереди. Новых фоновых обращений к игровому состоянию нет.
5. Пять тестов бюджета, шесть тестов очереди тиков и один тест совместимости бренда прошли. Живой сценарий проверил исключения из ограничения частиц и корректность реального здоровья при клиентском масштабе 40.
6. Исправлен тест генерации: неудачный future больше не считается сгенерированным чанком. Тесты используют новые миры и сохраняют исходные результаты, команды и контрольные суммы.
7. Проверены сборка, упаковка полного сервера, запрещённые вызовы, запуск пяти вариантов JVM и короткие функциональные нагрузки. Подробности: `local-verification.md`.

## Новый алгоритм запланированных тиков

LevelTicks сохраняет нижнюю границу ближайшего срока и пропускает полный обход контейнеров до этого срока. Более ранние вставки учитываются сразу; при повторном входе из tickCheck граница остаётся консервативной. Порядок очередей и выполнение блоков сохранены. Дифференциальный тест: 30 000 операций совпали с исходным кодом. Счётный тест: 1 000 → 1 полных обходов для 4 096 контейнеров за 1 000 тиков ожидания, с прежними 4 096 итоговыми событиями. Общий выигрыш MSPT пока не измерен.

## Подсистемы и следующие проверки

| Подсистема | Что установлено и что требуется |
| --- | --- |
| Сущности и коллизии | В сохранённом профиле значимы запросы EntityCollectionBySection, толкание и поиск целей. Перед изменением алгоритма нужны плотные и разреженные сцены, сохранение порядка результатов и границ AABB. |
| Здоровье игрока | LivingEntity.getHealth читает реальное здоровье CraftPlayer. Прямое чтение tracked data вернуло бы масштабированное здоровье. Нужны проверки respawn, teleport, damage и плагинов для любых дальнейших сокращений пути. |
| Tracking и metadata | Leaf уже фильтрует движение; фильтрация фитиля TNT Water остаётся опциональной. Нужна отдельная проверка смены фитиля API и порядка пакетов. |
| Чанки | Асинхронными очередями уже управляет Moonrise. Перед заменой очередей нужны отдельные профили загрузки, генерации с фиксированным seed и дискового I/O. |
| Тики, редстоун и block entities | Нужны сценарии порядка событий, соседних обновлений, пробуждения механизмов и плагинов. Пропуск вычислений без контракта пробуждения не обоснован. |
| Pathfinding и AI | Следует измерить WalkNodeEvaluator и POI жителей. Общие изменяемые буферы и доступ к миру из дополнительных потоков требуют доказательства владения данными. |
| Освещение | Нужны проверки зависимостей соседних чанков и снимки результатов распространения света в Moonrise/Starlight. |
| Сеть и клиент | Для частиц подсчитаны реальные пакеты. Block updates, level events, освещение и FPS реального клиента требуют отдельных сценариев. |
| Сохранения | Перед изменениями форматов Anvil/linear и очередей нужны save/reload, прерванные записи и проверка shutdown flush. |
| Планировщик и события | Должны сохраняться главный поток, порядок событий и задач. Анализ Folia сохранён; региональная модель потоков не внедрена. |

## Что остаётся открытым

- Полный аудит подсистем и профили на целевых мирах и оборудовании.
- Реальная нагрузка около 100 игроков, закрытые плагины, редстоун и сохранения.
- Длительный аптайм, рост памяти и стабильность GC.
- Повторяемое сравнение производительности JVM/GC; локальные фоновые проверки не выбирают победителя.
- FPS реального клиента, если заявляется его улучшение.

Гарантия онлайна, множитель ускорения и улучшение FPS пока не заявляются.

## Инструменты сборки

Paperweight core 2.0.0-beta.19 оставлен для зависимостей, маппингов и упаковки. Его задачи восстановления/применения/пересборки исходников отключены; корневой patcher-плагин удалён, файлов `.patch` в отслеживаемом дереве нет. Java в `src/minecraft` — обычные файлы Git, без вложенных репозиториев. Маппинги нужны для совместимости NMS-плагинов и не восстанавливают исходники из патчей.

Справка по закреплённой реализации: [PaperweightCore](https://github.com/PaperMC/paperweight/blob/v2.0.0-beta.19/paperweight-core/src/main/kotlin/io/papermc/paperweight/core/PaperweightCore.kt).
