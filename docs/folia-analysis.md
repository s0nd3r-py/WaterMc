# Folia: владение данными и применимость к WaterMc

Изучен локальный исходный репозиторий `D:/water-mc/folia-ref`, ревизия `73865e0e1c11752a03f30320e0521d4611221e08`. Основная реализация находится в `folia-server/minecraft-patches/features/0001-Region-Threading-Base.patch`. Путь описывает источник исследования; в WaterMc Java хранится напрямую.

## Архитектурные решения

| Механизм | Классы | Условие корректности |
| --- | --- | --- |
| Регионизация | ThreadedRegionizer, TickRegions | Регионы объединяются и разделяются вместе с переносом принадлежащих им данных. |
| Независимые тики | TickRegionScheduler | Регион выполняется владельцем; произвольный поток не может читать и менять его состояние. |
| Данные региона | RegionizedData, RegionizedWorldData | Списки сущностей, игроков и тиков принадлежат региону, а не общему изменяемому глобальному списку. |
| Проверки владения | TickThread.isTickThreadFor | Проверяется конкретная сущность, чанк или область, включая обращения на границах. |
| Передача задач | RegionizedTaskQueue, EntityScheduler | Работа для чужого владельца передаётся ему через очередь. |
| Перемещение | Региональные телепорты и перенос сущностей | Удаление из прежнего владельца и добавление новому согласованы с жизненным циклом сущности. |

Перенос одного пула потоков без переноса владения данными не воспроизводит Folia. Сущности на границе, слияние регионов, выгрузка чанков и смена владельца остаются частью задачи. Плотный спавн также не даёт того же распараллеливания, что разнесённые игроки.

## Что уже присутствует в исходной базе

- Moonrise управляет асинхронными очередями чанков, их зависимостями и I/O.
- TickThread содержит проверки владельца потока.
- Paper предоставляет совместимые интерфейсы планировщиков Folia. В этой базе `FallbackRegionScheduler` передаёт задачи глобальному планировщику. `FoliaAsyncScheduler` действительно использует фоновые исполнители и отдельный таймер. Нельзя описывать все эти интерфейсы как синхронные.
- Leaf содержит дополнительные опциональные асинхронные механизмы. Само их наличие не доказывает безопасный снимок всех данных мира и не является поводом включать их без отдельных проверок.

Точки проверки в WaterMc: `io/papermc/paper/threadedregions/scheduler` в основных исходниках и `ca/spottedleaf/moonrise/patches/chunk_system` в исходниках Minecraft.

## Решения для WaterMc

Сохраняется классическая семантика Bukkit/Paper: синхронные задачи и события выполняются владельцем игрового состояния. Новые изменения WaterMc не добавляют чтение или изменение живого мира из дополнительных потоков.

Допустимые кандидаты для дальнейшего выноса — чистые вычисления над неизменяемыми данными с явным возвратом результата владельцу. Для каждого нужны контракт снимка, отмена, обработка выгрузки и устаревшего результата. Существующий асинхронный код не заменяет такого доказательства.

Взрывы меняют мир последовательно: следующий видит изменения предыдущего. Простое распараллеливание меняет механику. Уже внесённые изменения сокращают расчётные накладные расходы и необязательные визуальные пакеты.

Новая оптимизация запланированных тиков сокращает обходы очереди на потоке владельца. Она не переносит выполнение блоков в фоновые задачи и проверяется относительно сохранённого исходного алгоритма.

Полная регионизация в WaterMc не внедрена: она потребовала бы отдельного контракта совместимости плагинов и переноса всех связанных данных. ТЗ требует использовать подходы Folia там, где они оправданы, с сохранением Bukkit/Paper API; механический перенос региональных потоков этим требованиям не соответствует.
