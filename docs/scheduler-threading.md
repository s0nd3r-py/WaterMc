# Планировщик и роли потоков WaterMc

## Фактическая база

CraftServer создаёт FallbackRegionScheduler. ThreadedRegionizer, TickRegionScheduler и RegionizedTaskQueue в производственных исходниках отсутствуют. Поэтому эта ветка не становится полноценным Folia с независимым владением регионами от одной замены очереди. Полный перенос Owned Regions остаётся отдельной незавершённой частью задачи. Существующие проверки владения миром сохраняются.

## Реализованные изменения

FoliaGlobalRegionScheduler принимает заявки через JCTools MpscUnboundedArrayQueue 4.0.6. Только поток tick() изменяет Long2ObjectOpenHashMap сроков. Граница producer index фиксируется в начале тика: непрерывные публикации не продлевают текущий drain. relaxedPoll не заставляет тик ждать производителя, зарезервировавшего слот. Просроченная заявка переносится на текущий тик при поступлении, а не теряется в прошедшем bucket. Сложение больших задержек насыщается на Long.MAX_VALUE.

Монитор stateLock удалён из глобального планировщика. Отдельный concurrent set хранит только metadata отмены задач, включая заявки в очереди и выполняющиеся периодические задачи; это не таблица игрового состояния. cancelTasks сохраняет немедленную отмену опубликованных задач. После отмены работающего repeat его состояние переходит из CANCELLED_RUNNING в CANCELLED после выхода callback. В глобальном и entity-планировщиках VarHandle чтение состояния исправлено с plain get на getAcquire.

Смешанные/вычислительные пулы чата, конфигурационной фазы и общих Bukkit/Folia async-задач используют platform threads, даже если устаревшие public flags выставлены сторонним кодом. Поля сохранены для совместимости, старые ключи этих четырёх VT-настроек больше не активируют virtual threads. Auth/download сохраняют отдельную поддержку виртуальных потоков для блокирующего I/O. Tick и существующий A* worker pool остаются platform threads. Это изменение не классифицирует произвольный код плагинов и не доказывает изоляцию каждого унаследованного I/O-компонента.

## Проверки

GlobalSchedulerTest проверяет deadlines, периодические и вложенные задачи, owner thread, 24 000 заявок от восьми производителей с FIFO каждого производителя, 20 000 заявок одновременно с tick(), отмену pending/future задач одного плагина и работающего repeat, аргументы и переполнение срока. ThreadRoleTest проверяет реальные Thread.isVirtual() в рабочих заданиях шести типов пулов. Это тесты действующего глобального планировщика; split/merge/телепорты Owned Regions здесь не реализованы и не заявляются проверенными.
