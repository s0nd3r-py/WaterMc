# Архитектурный раунд: данные, сохранение, события, диагностика (12 ноября 2026)

Статус по каждому пункту задания: **сделано**, **уже было** (и где), **не сделано** (с причиной).

## Модуль 1. Данные, сохранение, POI, конфиги

### Журналы `data/*.wdb` вместо JSON — сделано
- `ops`, `whitelist`, `banned-players`, `banned-ips`, `usercache` хранятся в `data/<имя>.wdb` (`org.watermc.storage.WaterRecordLog`).
- Формат: заголовок `WDB1` + записи `op | key | payload | CRC32C`. Добавление или удаление — одна дозапись, а не перезапись файла. Компакция (tmp → fsync → атомарная замена) запускается, когда журнал вдвое больше живых данных, и при штатном `save()`.
- Если компакция не удалась (на Windows замена файла запрещена, пока он открыт другим процессом), журнал переоткрывается, и дозапись продолжается в прежний, целый файл. Регрессионный тест — `WaterRecordLogTest.failedCompactionKeepsJournalWritable`.
- Все записи идут через один поток в порядке постановки. Прежнее асинхронное JSON-сохранение Leaf могло писать один файл из нескольких потоков одновременно.
- После аварии оборванный хвост (неполная запись или неверный CRC) отбрасывается, все предыдущие записи сохраняются.
- Нагрузка записи — исходный JSON-объект элемента, поэтому поля, добавленные плагинами, не теряются. Bukkit/Paper API (`BanList`, `getOperators`, whitelist, `OfflinePlayer`) работает через те же `StoredUserList` без изменений.
- Caffeine не используется: списки банов/OP/whitelist обязаны целиком находиться в памяти, вытеснение кэшем было бы ошибкой. Они и так лежат в `ConcurrentHashMap`.

### Миграция без потери данных — сделано
- При первом старте `data/<имя>.json` копируется в `data/migration-backup/` (существующие копии не перезаписываются). Затем записи импортируются в `.wdb`, журнал перечитывается и сверяется побайтово, и только после этого исходный JSON удаляется.
- Если JSON повреждён: копия в `migration-backup/`, исходник переименовывается в `*.json.corrupt`, список стартует пустым (как в Spigot), данные остаются в копии.
- Если `.wdb` уже существует, JSON больше не читается и не удаляется.
- **Совместимость:** внешние инструменты, которые читали `ops.json`/`whitelist.json` напрямую, больше их не увидят. Изменения нужно делать командами или через API.

### Согласованное сохранение — сделано частично
- `PersistenceBarrier`: при остановке и при `/save-all flush` сервер дожидается всех поставленных записей игроков (FIFO-маркер в однопоточном пуле `AsyncPlayerDataSaving`) и журналов `.wdb`, и только потом сбрасывает чанки.
- При обычном автосейве барьер не блокирует тик: игроки и чанки ставятся в очередь в одном тике, как раньше.
- Атомарности «инвентарь + сундук» при падении JVM в произвольный момент нет и без журналирования мира быть не может: файлы игроков и region-файлы пишутся независимо.

### POI — сделано (отступ), кэш — не нужен
- Paper ищет POI в памяти (`PoiAccess`), без диска; у жителей уже есть ритм 20–40 тиков и `JitteredLinearRetry` по позициям.
- Добавлен отступ после пустого поиска (`PoiSearchBackoff`): 20 → 40 → 80 тиков, но не больше `performance.poi-search-backoff.max-delay-ticks` (по умолчанию 100). Пока в мире не изменилась ни одна POI, поиск повторно не запускается. Любое добавление, удаление, загрузка или освобождение POI сразу отменяет отступ.

### Санитайзер конфигов и `/watermc reload` — сделано
- Ключи `watermc.yml`, которые не регистрирует ни один модуль, удаляются. Перед удалением их значения сохраняются в `config/legacy/removed-keys-*.yml`. Содержимое свободных секций (map-настроек) не трогается.
- Предупреждения о конфликтах:
  - bungeecord и velocity включены одновременно;
  - сервер за прокси, а connection-throttle > 0;
  - alternate keepalive Purpur вместе с send-multiple;
  - автосейв выключен при асинхронном сохранении игроков.
- Команда теперь называется `/watermc` (`/leaf` оставлен алиасом, права те же). `/watermc reload` перечитывает `watermc.yml` и `watermc-world.yml`.

## Модуль 2. События, CraftBukkit, компоненты, права

- **`PlayerMoveEvent` — сделано.** Если слушателей нет, пакет движения больше не создаёт 3 объекта `Location` и само событие. Обновление `lastPos*`, AFK-сброс Purpur и проверка `justTeleported` повторяют прежнюю логику побитово.
- **`BlockPhysicsEvent` — уже было** (флаг `hasPhysicsEvent` у Paper/Leaf).
- **Ранний выход `callEvent` без слушателей — уже было** (Leaf).
- **Копирование `ItemStack`/`Location`/`BlockState` — не сделано.** Контракт Bukkit API требует возвращать копии (`getLocation()`, `getState()` — снимок). Убрать копии значит сломать плагины, которые изменяют полученный объект.
- **Рефлексия в CraftBukkit — уже было.** Горячей рефлексии нет (см. предыдущий раунд).
- **Кэш сериализации Adventure `Component` — не сделано.** Компоненты переводятся под язык каждого игрока (`GlobalTranslator`) и кодируются в Netty на соединение. Общий кэш байтов без ключа по языку отдал бы игрокам чужой перевод. Это отдельная крупная задача.
- **Кэш `PermissibleBase.hasPermission` — не нужен.** Это уже один поиск в `HashMap`; `toLowerCase` для имён в нижнем регистре не аллоцирует.
- **Дифференциальный синк Brigadier — невозможен.** В протоколе есть только `ClientboundCommandsPacket` с полным графом команд; частичного обновления клиент не поддерживает.

## Модуль 3. Спавн, сетка, чанки, редстоун

- **Отсечка мобкапа — сделано** (`MobcapPrecheck`, `performance.mobcap-precheck.enabled`). После пересчёта счётчиков категория отбрасывается до обхода чанков, если лимит исчерпан у каждого игрока мира. Это консервативно: разрешённый спавн никогда не запрещается. Разница только в расходе ГСЧ на троттлинг Leaf.
- **Пространственная сетка для дропа и опыта — уже было.** `getEntitiesOfClass` в Moonrise ищет по посекционным спискам с разбивкой по классам (`ChunkEntitySlices`).
- **Бюджет активации чанков — не сделано.** Перевод чанков в FULL в Moonrise связан с тикетами и порядком загрузки; частичная активация с переносом на следующий тик требует отдельной проработки и нагрузочных тестов.
- **Редстоун — уже было.** В `paper-world-defaults.yml` есть `misc.redstone-implementation: ALTERNATE_CURRENT`.
- **Пакетный пересчёт света — уже было** (Starlight/Moonrise).
- **Нулевые аллокации в коллизиях движения — не сделано.**

## Модуль 4. Сеть, инспектор, watchdog, память

- **Netty-фильтр — не добавлялся.** В Paper уже есть `packet-limiter` в `paper-global.yml` (в Netty, до игрового потока), лимиты книг и `item-validation`, а также защита от огромных пакетов. Ещё один фильтр с собственными порогами давал бы ложные кики.
- **`/watermc inspect [секунды]` — сделано.** Топ-10 чанков по реальному времени тика (мс/тик) с разбивкой: сущности, block entities, воронки. Вне окна замера цена — одна проверка `volatile boolean` на сущность или block entity.
- **Watchdog плагинов — сделано.** Время слушателей синхронных событий и sync-задач замеряется по плагинам. Если плагин превысил порог за тик (`misc.diagnostics.plugin-watchdog.threshold-ms`, по умолчанию 15), в консоль выводится предупреждение с самым тяжёлым классом, не чаще раза в 30 секунд на плагин.
- **Heap guard — сделано частично.** Если после GC старое поколение заполнено выше 82%, сбрасываются холодные кэши (кэш секций пакетов, кэш Jade). Ускоренная выгрузка чанков не делалась: принудительная выгрузка из-под тикетов Moonrise небезопасна.

## Модуль 5. Drain, метрики

- **`/watermc drain [host:port]` — сделано.** По умолчанию команда доступна только консоли.
  1. Вход новых игроков закрывается.
  2. Онлайн-игроки переводятся на резервный узел через `Player#transfer` (`ClientboundTransferPacket`). Без адреса игроки отключаются с сообщением о перезапуске.
  3. Сервер ждёт выхода игроков (`misc.diagnostics.drain.timeout-seconds`), записи данных игроков и `.wdb`, затем штатно останавливается.
  4. Узел-получатель должен иметь `accepts-transfers=true`.
- **HTTP-метрики — сделано.** Выключены по умолчанию, по умолчанию слушают `127.0.0.1:9225`. `/metrics` отдаёт формат Prometheus, `/metrics.json` — JSON: TPS, MSPT, heap, чанки, сущности, игроки. Снимок собирается в основном потоке раз в 20 тиков, HTTP-поток не обращается к миру.
- **Консольный вывод — не менялся.** Paper уже использует асинхронный Log4j-аппендер TerminalConsoleAppender.

## Не проверено

Живой запуск с реальным клиентом: `drain` с переводом на второй узел, `inspect` на нагруженном мире, метрики с Prometheus. Выигрыш производительности бенчмарками не измерялся.
