# WaterMc 1.21.11 — что это и чем отличается от Leaf

WaterMc — форк [Leaf](https://github.com/Winds-Studio/Leaf) (а значит, Paper, Purpur, Gale, Pufferfish и Leaves) для Minecraft 1.21.11 на Java 21+. Он целиком совместим с Bukkit/Paper API: плагины, собранные под Paper, работают без изменений. Подавляющая часть оптимизаций движка унаследована от Leaf и его предшественников; их авторство и лицензии сохранены (`docs/inherited-attribution.md`, `licenses/`). Ниже перечислено только то, что WaterMc добавляет или меняет **поверх** Leaf.

Оговорка о доказательствах. У каждого пункта есть статус:

- **тесты** — проверено автоматическими тестами корректности (не скорости);
- **замер** — есть измеренная цифра, только на узком синтетическом сценарии;
- **не измерено** — эффект следует из устройства кода, но на скорость сервера не проверялся.

Сравнения WaterMc и Leaf по MSPT, CPU, памяти и GC в контролируемых условиях пока не проводилось (см. раздел «Бенчмарки»).

## 1. Запуск и структура сервера

| Что | Отличие от Leaf | Статус |
|---|---|---|
| Точка входа | `me.s0nd3r.watermc.WaterMain` вместо `org.bukkit.craftbukkit.Main`. Старый класс остаётся тонким делегатом с публичными полями `useJline`, `useConsole`, `BOOT_TIME` | тесты, живой запуск |
| Пакеты | Весь внутренний код сервера в `me.s0nd3r.watermc.*`: `core` (бывший `org.dreeam.leaf`), `integration` (`org.leavesmc.leaves`), `tuning` (`org.galemc.gale`), `engine` (Lithium), `runtime` (Pufferfish), `region` (Luminol), `seed` (Matter), а также собственный код WaterMc. Публичный API (`org.bukkit`, `io.papermc`, `com.destroystokyo`, `org.purpurmc`, а также `org.dreeam.leaf.event`, `org.leavesmc.leaves.*` и `gg.pufferfish.*` в модуле API) не переименован: на нём собраны существующие плагины. Внутренности Paper/Moonrise/Purpur на сервере тоже не перенесены | компиляция, тесты, живой запуск |
| Headless | Окно консоли (Swing/AWT) и всё его дерево классов удалены; проверки `GraphicsEnvironment` и AWT при старте нет | тесты |
| CLI | Белый список флагов для хостинг-панелей; клиентские и опасные (`--demo`, `--bonusChest`, `--eraseCache`, `--jfrProfile`, `--singleplayer`, `--safeMode`) отклоняются с понятной ошибкой. `nogui` принимается и игнорируется — иначе ломаются стандартные шаблоны Pterodactyl | тесты |
| Каталоги | Конфиги ядра в `config/`, служебные данные в `data/`, миры в `worlds/` (если в корне уже есть мир — корень остаётся). Старые файлы переносятся автоматически, существующие в новом месте не перезаписываются | тесты |
| Конфиги | `leaf-global.yml` → `config/watermc.yml`; все настройки `gale-global.yml` перенесены в его секцию `server-tuning` (значения подхватываются автоматически), мировые — в `watermc-world.yml`. Мёртвые ключи вычищаются с сохранением значений в `config/legacy/`; предупреждения о конфликтах между bukkit/spigot/paper/purpur/watermc | тесты |
| Бренд | `WaterMc` в логах, потоках, командах, метриках, `Bukkit.getName()`; JAR — `watermc-1.21.11.jar`; обращений к сервису обновлений Leaf нет. `isBrandCompatible` по-прежнему принимает бренды Paper/Gale/Leaf | тесты |

## 2. Данные и сохранение

| Что | Отличие от Leaf | Статус |
|---|---|---|
| `data/*.wdb` | `ops`, `whitelist`, `banned-players`, `banned-ips`, `usercache` хранятся в журнале с дозаписью (CRC32C на каждую запись, оборванный при аварии хвост отбрасывается, компакция через tmp + fsync + атомарная замена). Одно изменение — одна дозапись, а не перезапись всего JSON. Запись идёт одним потоком в порядке постановки. Обратная выгрузка в JSON: `/watermc data export` | тесты; выигрыш не измерен |
| Миграция | Исходные JSON копируются в `data/migration-backup/`, импортируются, перечитываются и сверяются побайтово, и только потом удаляются. Повреждённый JSON переименовывается в `.json.corrupt`. Поля, добавленные плагинами, сохраняются | тесты |
| Порядок сохранения | При остановке и `/save-all flush` сервер дожидается записи данных игроков и `.wdb` до сброса чанков (`PersistenceBarrier`) | тесты |
| Раскладка секций | По умолчанию — упакованное хранилище Paper/Leaf. Плоское `long[4096]` (`WaterSectionStorage`) только по опции `-Dwatermc.flat-section-storage=true`: замер показал, что оно удваивало кучу под чанки (833 против 393 МиБ на 1600 чанках) | замер: 385,2 МиБ у WaterMc против 393,2 МиБ у Leaf на одном мире (см. `docs/profile-2026-11-19.md`) |

Совместимость: внешние утилиты, читавшие `ops.json` или `whitelist.json` напрямую, больше их не увидят; изменения делаются командами и через API.

## 3. Производительность горячих путей (поверх Leaf)

| Что | Идея | Статус |
|---|---|---|
| `PlayerMoveEvent` | Если слушателей нет, пакет движения не создаёт событие и три `Location` | тесты; не измерено |
| Трекер сущностей | Дальность с учётом пассажиров, Y-дальность и позиция сущности считаются один раз на проход, а не на каждого игрока | не измерено |
| Мобкап | Категория отбрасывается до обхода чанков, если лимит исчерпан у всех игроков | тесты |
| Поиск POI | После пустого поиска житель ждёт дольше (до 100 тиков); любое изменение POI в мире сбрасывает задержку | тесты |
| Видимость AI (DAB) | Невидимый игрокам моб тикает реже: 1, 2, 4, 8, 16 … тиков; бой, урон и ближний игрок возвращают частоту | тесты |
| Запланированные тики | Нижняя граница ближайшего срока: 4096 контейнеров за 1000 тиков ожидания — 1 полный обход вместо 1000 при тех же итоговых событиях | замер (счётчик обходов, не MSPT) |
| Блокировки | `NodeEvaluatorCache` (async pathfinding) без глобального монитора; `SyncLongOpenHashSet` на блокировке чтения-записи; планировщик глобального региона на MPSC-очереди | тесты |
| Старт | Ленивый DFU (схемы строятся при первом реальном преобразовании). Ремаппер плагинов включён по умолчанию: маппинги читаются только при реальной необходимости, хэши jar кэшируются по размеру и времени изменения, кэш в `plugins/.water-remapped` | тесты |
| Консоль | Язык вывода в терминал: `misc.console.language: en / ru / uk` в `watermc.yml` или `-Dwatermc.console.language`. Файл журнала остаётся на английском, строка готовности `Done (…)` не переводится | тесты |
| Тик-цикл | Короткое активное ожидание в конце тика (`watermc.tick-spin-nanos`, по умолчанию 50 мкс) | не измерено |
| Сеть и диск | Нативное сжатие регионов (libdeflate) и опциональный ZSTD; один сжатый пакет секции делится между наблюдателями (по умолчанию 64 МиБ кэша) | тесты; выигрыш не измерен |
| Редкие замены | Guava Cache → Caffeine, `SimpleDateFormat` → `DateTimeFormatter` (в `PlayerList` один статический форматтер использовался из разных потоков — гонка данных), `StringBuffer` → `StringBuilder` | тесты |
| Взрывы и частицы | Опциональные (по умолчанию выключены) лимит визуальных пакетов взрывов и бюджет ванильных частиц. Пакеты с отдачей игрока никогда не отбрасываются | замер: 24 600 → 15 960 пакетов частиц в синтетическом сценарии |
| Математика | Точный `Math.fma` по умолчанию на всех CPU (неточная замена только по явному флагу) | тесты |
| Поиск соседних сущностей | Список сущностей секции хранит плоскую копию габаритов (`double[]`), её обновляет `Entity.setBoundingBox`. Проверка пересечения не обращается к объектам сущности и `AABB`. Отключение: `-Dwatermc.packed-entity-bounds=false` | замер профилем: толкание в толпе из 600 мобов 21–25% → 10–11% основного потока; живая самопроверка без расхождений |
| Команда сущности | `Entity.getTeam()` у не-игрока сразу возвращает `null`, если ни в одной команде нет записи с ключом длины UUID | тесты; замер профилем: 1,3–1,8% → 0,4–0,6% |
| Толкание | Поиск соседей для толкания останавливается, найдя `max(maxEntityCramming, max-entity-collisions)` сущностей; если этого не хватает для решения о давке, ищет полный список. Отключение: `-Dwatermc.limited-push-query=false` | дифференциальный тест (200 000 случаев); выигрыш в пределах шума |
| Генерация мира | Пул генерации чанков: 4 ядра → 2 потока (было 1), 8 → 5, 16 → 9; явная настройка `chunk-system.worker-threads` главнее. Пока миры готовятся при запуске, генерация идёт на всех ядрах (основной поток в это время только ждёт чанки), затем пул возвращается к обычному размеру. Отключение ускорения: `-Dwatermc.startup-worker-boost=false` | тесты; замер — в работе |
| Поиск биома | Границы узлов R-дерева климата — один плоский `long[14]` вместо массива объектов `Parameter`, цикл развёрнут; та же целочисленная математика | тест побитового совпадения (200 000 случаев) и сверка с полным перебором (20 000) |
| Сферы опыта | Слияние новой сферы с существующей останавливается на первом совпадении и ищет по индексу типа сущности, а не перебором класса | не измерено |
| $-переменные скриптов | Сохранение раз в минуту кодирует только изменённые переменные и списки, а не все переменные заново | тесты |

Прогретые проверенные пути (чтение и запись `WaterSectionStorage`, FastAABB, TPS-кольцо) выделяют 0 байт. Это **не** означает нулевых аллокаций всего тика (см. `docs/memory-footprint-audit.md`).

## 4. Инструменты администратора

- `/watermc inspect [секунды]` — топ-10 чанков по реальному времени тика с разбивкой на сущности, block entities и воронки. Вне окна замера стоит одна проверка `volatile boolean`.
- Watchdog плагинов — замеряет слушатели и синхронные задачи; при превышении порога (15 мс за тик по умолчанию) в консоль идёт предупреждение с плагином и самым тяжёлым классом. Первые 60 секунд после запуска (холодный JIT, загрузка классов) предупреждения не выводятся; встроенные функции WaterMc подписаны как «WaterMc» / «WaterMc scripts», а не как плагин «Minecraft».
- Watchdog Netty — раз в секунду ставит в каждый сетевой поток крошечную задачу-пульс. Если поток не ответил 10 секунд (`diagnostics.netty-watchdog.stall-seconds`), в лог идёт его стек — видно, какой обработчик пакетов завис; после восстановления — отдельная строка. Зависший сетевой поток замораживает пакеты всех игроков на нём, а обычный watchdog основного потока этого не видит.
- Аудит безопасности (`diagnostics.security-audit.*`) — выдача и снятие OP, консольные команды от плагинов, переход в творческий режим или режим наблюдателя, выключение плагина во время работы. В каждой строке назван плагин, чей код сделал вызов (первый класс из загрузчика плагина в стеке). `stack-traces: true` добавляет полный стек — так находят бэкдор, вшитый в плагин, вплоть до класса и метода.
- Heap guard — при заполнении старого поколения выше 82% **после GC** сбрасывает холодные кэши.
- `/watermc drain [host:port]` — закрыть вход, перевести игроков на другой узел пакетом `ClientboundTransferPacket`, дождаться записи данных и остановить сервер.
- `/watermc data [list]` — журналы `data/*.wdb`: число записей, размер. `/watermc data export <имя|all>` — читаемая JSON-копия в `data/export/` (списки сервера — в ванильном виде массива, остальные — объект ключ → значение). Работа с файлами идёт вне основного потока, сам журнал не изменяется.
- HTTP-метрики (Prometheus и JSON) — выключены по умолчанию; снимок собирается в основном потоке раз в 20 тиков.
- `/watermc script reload | status | functions` — управление скриптами (см. ниже).

### Исправления игровых ошибок

- **Дюп через предмет торговли жителя (1.21.6+).** Пока игрок держит рядом товар для обмена, житель показывает в руке копию результата сделки (шанс выпадения 0). С 1.21.6 ножницы снимают с любого моба снимаемое снаряжение (сёдла, конскую броню, ковры) без учёта шанса выпадения, а заражение жителя переносит снаряжение зомби-жителю: копию можно было забирать бесплатно и сколько угодно. Теперь показанный предмет нельзя снять ножницами, а при заражении он убирается из руки. Настоящие предметы в руке жителя (шанс выпадения выше 0) не затрагиваются.

## 5. Скриптовый движок WaterScript

Встроен в ядро (`me.s0nd3r.watermc.script`): файлы `scripts/*.wsc`, события, команды с правами, таймеры, функции, `wait` без блокировки сервера, `$`-переменные в `data/script-variables.wdb`. Скрипты компилируются при загрузке: ошибки видны сразу, с файлом и строкой. Лимит операций, песочница без доступа к файлам, сети и рефлексии. Справочник: [scripting.md](scripting.md). Статус: тесты (19), скорость относительно Skript и Denizen не измерялась.

## 6. Где WaterMc, вероятно, сильнее Leaf

Это гипотезы, следующие из устройства кода. Они **не подтверждены** замерами.

| Сценарий | Почему ожидается выигрыш | Что должно показать замер |
|---|---|---|
| Сервер с тысячами банов и частыми изменениями списков | Дозапись вместо перезаписи всего JSON при каждом изменении | время и объём записи на диск при 1000 изменений |
| Старт сервера и перезагрузка | Ленивый DFU, ленивые маппинги ремаппера, кэш хэшей jar, отсутствие GUI | время до `Done`, пик heap на старте |
| Много игроков, на сервере нет плагинов с `PlayerMoveEvent` | Нет объекта события и трёх `Location` на каждый пакет движения | аллокации в секунду (JFR), частота GC |
| Деревни с безработными жителями | Реже повторные поиски POI | доля тика в `AcquirePoi` (профиль) |
| Много игроков в одном регионе | Один сжатый пакет секции на всех наблюдателей | CPU на сжатие при массовом входе в область |
| Сохранение больших миров | Нативное сжатие регионов | CPU и длительность автосохранения |
| Операции и отладка | Watchdog, inspect, drain, метрики встроены | не бенчмарк: удобство и время диагностики |

## 7. Где WaterMc не лучше

- На типичном игровом тике основная производительность определяется тем же унаследованным кодом, что и в Leaf. Заметной разницы по MSPT на стандартной нагрузке ожидать не следует, пока она не измерена.
- Полных регионов Folia нет (только запасной планировщик): при большом числе игроков, разбросанных по огромному миру, Folia масштабируется по ядрам лучше.
- Расход памяти JVM выше, чем у серверов на Rust вроде Pumpkin: у них нет ни JIT-прогрева, ни метаданных классов, но нет и полной ванильной механики с поддержкой Paper-плагинов.
- Асинхронный поиск пути остаётся экспериментальным и по умолчанию выключен.

## Бенчмарки: протокол без выдуманных чисел

Стенд `benchmarks/` (`run-native.py`, боты, WaterBench) уже умеет сценарии `compat`, `explosionpackets`, `particles`, `tntburst`, `entities`, `chunkgen`, `soak`. Для честного сравнения с Leaf нужно:

1. **Отдельная машина** (или изолированные ядра) без игр, браузера и других нагрузок; фиксированная частота CPU; одинаковые JDK и флаги JVM.
2. **Один и тот же мир** для обоих ядер (копия), одинаковая предзагрузка чанков; Leaf — той же ревизии 1.21.11 (`docs/upstream-provenance.json`).
3. **Не менее 5 прогонов** на сценарий, медиана и разброс. Метрики: MSPT p50/p95/p99 (а не только TPS), CPU, аллокации в секунду, паузы GC, RSS.
4. Результаты — в `benchmarks/results/<дата>-vs-leaf/` вместе с командами, SHA JAR и логами.

| Сценарий | Есть в стенде? | Метрика | Leaf | WaterMc | Δ |
|---|---|---|---|---|---|
| Время старта до `Done` (холодный, 10 запусков) | нужно добавить | секунды, пик heap | — | — | — |
| 1000 изменений бан-листа при 5000 записей | нужно добавить | байт на диск, время | — | — | — |
| 100 ботов бегают по новому миру (`chunkgen` + движение) | частично | MSPT p95, аллокации/с | — | — | — |
| Деревня из 100 жителей без рабочих мест, 10 минут | нужно добавить | доля тика в `AcquirePoi` | — | — | — |
| 100 игроков входят в одну область | нужно добавить | CPU на сжатие, MSPT | — | — | — |
| `tntburst`, `entities` | да | MSPT p95 | — | — | — |
| Автосохранение 20 000 чанков | нужно добавить | длительность, CPU | — | — | — |
| `soak:40:3600` (час) | да | рост heap, MSPT со временем | — | — | — |

Пустые ячейки заполняются **только** результатами этих прогонов. До этого в отзывах и описаниях проекта не стоит писать «быстрее Leaf на N%».

## Переход на WaterMc с Paper, Spigot, Purpur или Leaf

Достаточно положить `watermc-1.21.11.jar` в каталог существующего сервера и запустить. При первом старте:

| Что было | Куда переносится |
|---|---|
| `bukkit.yml`, `spigot.yml`, `purpur.yml`, `commands.yml`, `help.yml`, `permissions.yml` | `config/` |
| `config/leaf-global.yml`, `config/gale-global.yml`, `config/gale-world-defaults.yml` | `config/watermc.yml` (значения Gale — в секцию `server-tuning`), `config/watermc-world.yml` |
| `ops.json`, `whitelist.json`, `banned-players.json`, `banned-ips.json`, `usercache.json` | `data/*.wdb`; исходники байт в байт в `data/migration-backup/` |
| `version_history.json`, `.console_history`, `map-color-cache.dat`, `syncmatics/`, `replay/` | `data/` |
| `codeofconduct/` | `config/codeofconduct/` |
| `debug/`, `dumps/`, `crash-reports/` | `logs/` |
| `tuinity.yml`, `airplane.yml`, `leaves.yml`, `mirai.yml`, `petal.yml`, `divinemc.yml` и др. | `config/legacy/` (без изменений) |
| миры в корне (`world`, `world_nether`, `world_the_end`, миры Multiverse) | `worlds/` |
| устаревшие ключи в `watermc.yml` | удаляются, значения — в `config/legacy/removed-keys-*.yml` |

Правила безопасности:
- **Ничего не удаляется** и не перезаписывается. Если файл уже есть в новом месте, старый остаётся и попадает в отчёт.
- **Миры переносятся по принципу «всё или ничего»:**
  - если какой-то мир занят другим процессом (`session.lock`) или в `worlds/` уже есть мир с тем же именем, все миры остаются в корне, и сервер работает с корнем как раньше;
  - при сбое посреди переноса уже перенесённые миры возвращаются обратно;
  - отключить перенос миров: `-Dwatermc.upgrade.move-worlds=false`;
  - миры не трогаются вообще, если каталог миров задан явно (`--world-dir` или `settings.world-container`).
- **Отчёт.** Всё, что сделано, записывается в `data/upgrade-report-*.txt`.
- **Плагины с жёстко прописанным путём** вида `world/…` (резервные копии, карты) нужно перенастроить на `worlds/world/…`. Плагины, которые берут путь через Bukkit API, работают без изменений.

**Проверено живым переходом** (`D:/water-mc/run/upgrade-leaf-to-watermc-1`, 19 ноября 2026). Сначала исходный Leaf создал сервер: три мира, OP, whitelist, бан игрока и IP. Затем на том же каталоге запущен WaterMc:
- миры перенесены в `worlds/`, `uid.dat` совпадают побайтово, все region-файлы на месте;
- списки читаются командами `whitelist list` и `banlist`;
- исходные JSON сохранены без изменений;
- нового мира в корне не создано;
- код выхода 0, исключений нет.

Автотесты: `ServerUpgradeTest` (8), в том числе откат при сбое посреди переноса.

## Оставшиеся недоделки (по приоритету)

1. **Нет сравнения с Leaf по скорости.** Это главный пробел для любых заявлений о скорости (см. протокол выше).
2. **Асинхронный поиск пути** (opt-in, выключен) читает живой мир из рабочего потока. Нужен неизменяемый снимок или удаление режима.
3. **Бюджет активации чанков** при массовых телепортах не реализован.
4. **Коллизии движения** игрока всё ещё выделяют объекты на каждом пакете.
5. **Heap guard** только сбрасывает кэши и не ускоряет выгрузку неактивных чанков.
6. **Скрипты**: мало событий; `chat` нельзя отменить.
7. **Внутренние имена.** Классы в перенесённых пакетах частично сохранили исторические имена (`LeavesProtocolManager`, `AsyncPathProcessor` и т.п.), комментарии `// Leaf - …` / `// Paper - …` в ванильном коде сохранены намеренно: это пометки происхождения правок.
