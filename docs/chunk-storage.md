# Chunk-Storage: контракт WaterMc

Секции блоков с глобальным реестром более 256 состояний используют `WaterSectionStorage` через совместимый фасад `PalettedContainer`. Биомы и малые пользовательские реестры сохраняют исходную реализацию. Адрес клетки: `(y << 8) | (z << 4) | x`.

## Память и потоки

Однородное хранилище содержит только ID состояния. Массив `long[4096]` (32 КиБ полезных данных) публикуется CAS при первом отличающемся значении. Присваивание прежнего состояния не материализует массив. Загрузка однородной секции с лишними записями локальной палитры также не требует массива.

Чтение ссылки массива и клетки выполняется через `VarHandle.getAcquire`, запись клетки — `setRelease`, обмен — атомарный `getAndSet`. Обычные мутации плоского контейнера не захватывают монитор палитры. Это не разрешение менять мир с чужого потока: счётчики секции, списки тикающих блоков и остальные данные чанка по-прежнему принадлежат владельцу чанка. Копирование, загрузка и сериализация требуют владельца либо изолированного снимка. Снимок не является транзакцией относительно параллельных записей.

## Диск, клиент и Anti-Xray

`pack/unpack` сохраняют исходный формат NBT. На границе протокола глобальные ID переупаковываются в отдельную локальную палитру, а при более 256 состояниях — в глобальный формат. Однородные секции используют нулевую разрядность, поэтому воздух не отправляется как полный массив глобальных ID. Биомы не меняют формат.

Пакетная палитра включает резервные состояния Anti-Xray; `ChunkPacketInfo` получает разрядность, палитру, смещение и preset values именно записанного пакета. Изменение живого контейнера после записи не меняет эту палитру. Сериализация и построение снимков выделяют память; гарантия 0 байт относится к прогретым get/set/getAndSet, а не к упаковке пакетов.

## Проверки

`WaterSectionStorageTest`: случайные операции и битовые снимки относительно `SimpleBitStorage`, границы, независимость копий, конкурентная первая материализация и соседние клетки, измерение аллокаций через ThreadMXBean.

`SectionContainerCompatibilityTest`: YZX-адресация, mutators/copy/recreate, NBT, локальные и глобальные пакеты, нулевая палитра воздуха/камня, загрузка однородной секции с лишними entries, счётчики секции, metadata Anti-Xray и переписывание пакета существующим `BitStorageWriter`, отсутствие монитора на плоских мутациях. Это проверки формата и механизма переписывания; отдельный живой серверный прогон всех режимов Anti-Xray ими не заменяется.
