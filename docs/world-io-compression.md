# World IO и сжатие WaterMc

Обычный Anvil ZLIB (ID 2) по умолчанию сохраняется: writer использует Velocity compressor уровня 1–3 (watermc.region-compression-level, default 3). Фактический provider определяется Natives.compress.getLoadedVariant(); на платформе без libdeflate остаётся Java fallback. Старые GZIP, ZLIB, LZ4 и несжатые чанки читаются прежними reader-ами. Нельзя подставлять предполагаемый размер в native inflate: старый Anvil не содержит точной длины распакованного чанка.

Нативный ZSTD доступен через unsupported-settings.compression-format: ZSTD. Он использует предусмотренный Anvil custom marker 127 + writeUTF("watermc:zstd") + ZSTD frame, а не занимает чужой стандартный compression ID. ZSTD reader использует zstd-jni. Такие новые записи требуют WaterMc либо другого reader с поддержкой watermc:zstd; обычный ZLIB остаётся форматом по умолчанию для переносимости. External .mcc использует тот же custom header. Неизвестный custom codec явно отклоняется.

NativeRegionOutputStream буферизует исходный NBT один раз, без toByteArray-копии, и bulk-сжимает на существующем compression executor. Все native buffers и compressor закрываются даже при ошибке; RegionFile ChunkBuffer закрывается (коммитится) только после успешного сжатия и записи. Предельная распакованная длина ограничена MAX_CHUNK_SIZE. Пиковая временная память включает raw NBT и compressed output; загрузка/сжатие не являются zero-allocation. Flush не коммитит незавершённый кадр, финализация происходит при close.

Moonrise уже отделяет disk IO, performReadDecompress на compressionExecutor и ChunkDataLoadTask.runOffMain на loadExecutor, где выполняются upgradeChunkTag, parse и подготовка ProtoChunk. Owner hooks остаются runOnMain. Не добавлен второй дублирующий пул. CompoundTag.copy в callbacks сохраняются: pending write и несколько concurrent readers должны владеть разными изменяемыми деревьями. Их слепое удаление создало бы гонки.

Flat PalettedContainer.pack теперь собирает только реальные global ID через primitive map; нет временного HashMapPalette шириной всей global registry. Compact section не создаёт int[4096]. Однородные counts используют общий FULL_LIST. SectionPacketCache хранит неизменяемую упакованную палитру/bit storage для повторных наблюдателей; Логическая invalidation вызывается всеми изменяющими flat mutators и только обнуляет volatile slot: в горячей мутации нет обращения к Caffeine/его locks. Прежний снимок остаётся в ограниченном глобальном бюджете до замены либо eviction. Weak keys и weak source-data reference исключают удержание живого контейнера global cache. Бюджет 32 MiB, watermc.section-packet-cache-bytes=0 отключает. Снимок по-прежнему требует владельца чанка или его изолированной копии, а не concurrent writer; opt-in старый async sender не стал транзакционным world snapshot.

CompressionEncoder возвращает shared direct read-only frame через retainedDuplicate. SharedPacketCompressionCache по умолчанию 64 MiB (watermc.shared-compression-cache-bytes, 0 отключает), expireAfterAccess 2 s, минимум 4096 bytes (watermc.shared-compression-min-bytes, минимум 256). Вес учитывает исходные bytes, compressed bytes и metadata. Уровень Caffeine admission/eviction допускает приблизительное временное превышение бюджета при concurrent loads. Cache owner release идемпотентен; eviction, expiry и close освобождают owner reference, очереди каналов владеют своими references. Unpooled backing предотвращает ABA при lookup/eviction race. Полный byte comparison после hash+size обязателен. Различные Anti-Xray/registry/protocol результаты не разделяют frame даже при совпавшем хеше.

Varint21LengthFieldPrepender использует CompositeByteBuf из малого direct header и retained payload slice; NIO gathering write не копирует общий payload. CipherEncoder делает writable per-connection copy перед in-place encryption для shared/read-only/composite input. Разные ключи клиентов не изменяют общий plaintext. При отключённом шифровании compressed payload разделяется вплоть до транспортного write. Плагины/транспорт могут добавлять собственные копии. Сериализация отдельных пакетных заголовков/NBT для разных packet objects сохраняется; кэш секций устраняет доминирующую повторную упаковку sections, exact-wire cache — повторное сжатие, а не всю сериализацию произвольных пакетов.

Тесты проверяют реальные Anvil и external files, legacy fixtures, форматы NBT, исключения/commit, refCnt=0, collision, racing close/eviction, framing и per-client cipher. Эти тесты не заменяют нагрузочный MSPT/RAM benchmark или живой тест сторонних plugins/Anti-Xray.

Connection.setupCompression создаёт отдельные native contexts encoder/decoder только при установке handlers. Повторная смена threshold не создаёт новых объектов compressor; handler removal закрывает принадлежащий ему compressor либо Java Deflater/Inflater. Устранены лишний context при реконфигурации и совместное владение одним объектом двумя handlers.
