# Приёмка по разделам ТЗ

Статус «реализовано» относится к конкретному изменению, «проверено» — только к указанному сценарию. Наличие исходников не означает полный аудит. Эта таблица обновляется по фактическим результатам.

| Раздел ТЗ | Сделано | Что ещё требуется для закрытия |
| --- | --- | --- |
| 1. Исходный код | Полный перенос в собственный Git; прямые Java-изменения взрывов/FMA/TNT/частиц; оптимизация очереди тиков проверена по исходному алгоритму на 30 000 операций | Полный аудит, профили оставшихся горячих путей и подтверждённые изменения по их результатам |
| 2. Folia | Исследованы владение регионами, очереди и планировщики; зафиксирована ревизия и ограничения переноса; игровая работа не перенесена в новые фоновые потоки | Обоснование и проверка каждого дополнительного асинхронного кандидата, если профили подтвердят необходимость |
| 3. Подсистемы | Карта точек входа; функциональные TNT/сущности/чанки; добавлен сценарий compat для тиков, редстоуна, block entities, пути, света, сохранений, событий и задач | Успешный запуск новых проверок, широкий аудит и нагрузки для каждой подсистемы, включая сбои диска и границы коллизий |
| 4. Клиентская нагрузка | Опциональные визуальные ограничения TNT/взрывов; новый бюджет частиц с реальным A/B подсчётом; существующая группировка block/light updates изучена | Отдельная проверка состояния реального клиента, массовых разрушений и FPS; пакетные числа не заменяют FPS |
| 5. JVM/GC | Проверен старт пяти комбинаций и короткие серверные нагрузки, Windows-адаптация MeowIce с записью исключённых флагов | Сопоставимые повторные CPU/RAM/GC замеры и длительная стабильность на целевом сервере |
| 6. Плагины | API побайтово сохранён; тестовый плагин использует публичные API; проверено здоровье; расширен сценарий задач и событий | Реальные закрытые плагины пользователя и их сценарии |
| 7. Измерения | Исторические JFR и GC/тик/пакетные данные; новые сырые функциональные данные и команды; сравнение количества обходов очереди выполнено без зависимости от фоновой нагрузки | Новые контролируемые профили, JMH, длительные нагрузки и целевое A/B с повторениями; async-profiler в поддерживаемом окружении |
| 8. Разработка | Логические коммиты, сохранённый старый проект, отключённые по умолчанию визуальные ограничения, тесты и повторяемый стенд | Продолжать проверки после каждого следующего существенного изменения |
| 9. Итоговая цель | Собран отдельный работающий исходниковый форк WaterMc | Подтверждение целевого онлайна около 100, стабильности и совместимости на 7950X3D/192 ГБ |

Текущее окружение позволяет продолжать код, функциональные и пакетные проверки. Пользователь играет; выводы об ускорении из новых временных метрик здесь не делаются. Целевые миры, сервер и закрытые плагины отсутствуют, поэтому соответствующие строки нельзя объявить выполненными.
