# Микротест выбора запланированных тиков

Это отдельный JMH-проект. Он загружает классы из конкретного полного WaterMc JAR и сравнивает новый LevelTicks с сохранённым исходным алгоритмом из fbf8d34. Корневая сборка сервера от JMH не зависит.

## Подготовка

Нужны JDK 21 для компиляции и Python 3.9+. Из корня репозитория:

```text
python benchmarks/micro/prepare-runtime.py --jar watermc-server/build/libs/watermc-1.21.11.jar
./gradlew -p benchmarks/micro writeRuntimeClasspath
```

В PowerShell используйте `.\gradlew.bat`. На этом компьютере перед Gradle через Git Bash выполняется `source /d/water-mc/env.sh`, чтобы кэш и временные файлы оставались на D:.

Подготовщик проверяет контрольные суммы вложенного сервера и библиотек и создаёт отдельный каталог, названный SHA-256 JAR. Старые каталоги не удаляются. Путь к classpath записывается в `build/runtime-classpath.txt` этого проекта.

Короткая фоновая проверка запуска:

```text
python benchmarks/micro/run-jmh.py smoke-1 --java /path/to/jdk/bin/java --functional-only
```

В Windows путь к java.exe передавайте в кавычках. Такой запуск использует пониженный приоритет, один короткий прогрев и измерение, без отдельного fork. Он проверяет работоспособность стенда. Его значения ns/op не являются доказательством ускорения.

## Нагрузки

- FUTURE: все сроки в далёком будущем; новый алгоритм может пропускать обходы.
- MIXED: один просроченный контейнер недоступен для тиков, остальные ожидают; обход остаётся необходимым.
- DISABLED: все контейнеры просрочены, но не тикаются.
- DUE_BUDGET0: все готовы, лимит выполнения 0; проверяются сбор и возврат контейнеров без выполнения событий.

Размеры: 64, 4 096 и 16 384 контейнера. Время игры растёт на каждом вызове. После прогона проверяется, что ни один тик не выполнен при нулевом лимите.

Полный запуск без `--functional-only` использует пять прогревов, пять измерений и три fork, а также GC-профайлер. Его следует выполнять в контролируемом окружении с одинаковыми JVM/кучей. Это микротест конкретной очереди, не нагрузка 100 игроков и не множитель TPS всего сервера.

Исходные JSON, лог и команда сохраняются в `benchmarks/results/<дата>-micro/<метка>`. Повторная метка запрещена. Методика аннотаций и изоляции опирается на [документацию OpenJDK JMH](https://github.com/openjdk/jmh/blob/master/README.md) и [пример состояний](https://github.com/openjdk/jmh/blob/master/jmh-samples/src/main/java/org/openjdk/jmh/samples/JMHSample_03_States.java). Используется закреплённая версия 1.37.
